逐模型评价

PER-MODEL REVIEW

🏆 deepseek-v4-flash —— 「最高效全能王」主对话主力

失败率 5.9%（全系最低）· 会话最快（10.4min）· 成本 $0.05 · 每轮 12.9s（在复杂工具编排下可接受）

结论：主对话选它完全正确——「快 + 稳 + 便宜」三角最优。

🥈 glm-5.2 —— 「稳健执行者」代码/执行主力

失败率 7.5%（第二低）· 工具种类最广（10 种）· 执行快（11.3s）· 完成 3 并行长任务

结论：代码/执行路由正确——「多面手」定位，execute_code 11.9% 失败是 sandbox 环境问题。

🥉 k3 (Kimi) —— 「深度思考者」金融/核验主力

失败率 7.8% · 每轮 21.6s 最慢 · 会话最长 473min · 工具调用少（51 次，重思考轻操作）

结论：金融核验/深度推理用它对——两次核验都发现主报告遗漏的关键事实（预付款暴增 443%、子公司账户冻结 3.96 亿）。慢是特性不是缺陷。

⚠️ deepseek-v4-pro —— 「过气主力」备用

失败率 11.7%（最高）· execute_code 24.2% / skill_manage 30.8% / delegate_task 22.2%

结论：pro 路由备用即可——问题在工具编排纪律（错误路径反复试），不在智力。被 flash（主对话）+ k3（子代理）双重取代。

🗑 deepseek-chat / reasoner —— 已淘汰

chat：execute_code 8/8 全败（100%）· reasoner：6.89M token + 401M 缓存读（历史包袱），memory 38.9% 失败

结论：历史数据保留，无新任务。

三个关键判断

KEY INSIGHTS

① 失败率分布 = 工具环境问题 > 模型智力问题

高失败集中在 execute_code（sandbox）、terminal（网络/限频）、memory（容量满）、skill_manage（symlink 坑）——这些是 Hermes 配置问题，换哪个模型都一样。模型间真实差异（<4pct）远小于环境差异。

② 路由决策已被数据全面验证

flash（主对话）+ glm（代码）+ k3（深度核验）= 失败率最低组合。pro 退役正确。这不是拍脑袋，是 102 个会话 4000+ 次调用跑出来的。

③ 「最慢的模型，干出最深的活」

k3 21.6s/轮 = 更多推理 = 发现级输出。glm 11.3s = 稳健执行。flash 12.9s = 高频稳定。这就是模型路由的意义：让每个任务找到它该有的「速度 × 深度」组合。

分享会金句：「模型是插槽，Harness 是主板——最贵的插槽不一定最好，匹配任务的那个才是。」

数据来源：Hermes state.db（sessions / messages 全量表，2026-07-01 ~ 08-12，102 会话 4000+ 工具调用）+ async_delegations 回执。失败判定：工具结果 JSON error≠null 或 exit_code≠0。成本为估算（部分 provider 无定价条目显示 $0）。
