前言 · AI 下半场

FROM FOUNDATION MODELS TO AGENTS

过去三年的主线是模型的军备竞赛——更大的参数、更强的榜单分数。但当模型能力越过「可用」门槛之后，竞争焦点正在转移：谁能让 AI 真正进入工作流程、交付可验收的结果。

一个被忽视的事实：模型本身不干活，干活的是「模型 + 它周围的一切」。那个「周围的一切」——工具调用、上下文管理、记忆、编排、权限、沙箱、观测——业界统称为 Harness（缰绳 / 工作台）。

「你听到的所有 'AI 生产力神话'——Claude Code 半小时重构一个项目、Agent 自主跑完一单研究——都是 Harness 的功劳，模型只是其中被调度的执行单元。」
核心主张：模型决定「潜力上限」，Harness 决定「交付下限」。同一个人，配不同工具，产出完全不同——Agent 同理。
1

Harness 是什么

NOT A WRAPPER, BUT THE OTHER HALF OF THE BRAIN

1.1 定义：模型 = 大脑，Harness = 神经系统 + 身体

把模型比作一个极其聪明但「瘫痪」的天才：它什么都知道，但没有手、没有眼、没有记忆、不能行动。Harness 就是给它装上的——

能力裸模型（Chat 界面）模型 + Harness（Agent）
行动只能输出文字调用工具：读写文件、执行命令、调 API、操作浏览器
记忆对话结束即遗忘持久记忆：偏好、历史、项目上下文跨会话保留
感知只能读你贴进来的文本读取文件、网页、数据库、多模态输入
规划一次性回答拆解任务、多步执行、失败重试、反思修正
边界无权限概念权限控制、审批流、沙箱隔离、审计日志

1.2 澄清三个常见误解

误解一：「Harness 只是包装，模型强就行」 —— 错。同一个模型跑在不同 Harness 里，效果差异可以是「不可用」到「惊艳」（见第五章证据）。

误解二：「Harness = Agent 框架」 —— 不准确。框架（LangChain 等）是开发库；Harness 是运行环境 + 工具链 + 治理的完整系统。Claude Code、Codex、ZCode、DeepSeek Harness、OpenClaw、Hermes 都是 Harness。

误解三：「Harness 是工程问题，不是研究问题」 —— 部分错。上下文工程、记忆架构、工具调用协议至今没有最优解，是当前最活跃的研究前沿。

Harness 之于模型的意义

WHY THE HARNESS MATTERS MORE THAN THE MODEL

2.2 意义二：Harness 决定「模型能力的兑现率」

模型的真实能力 = 理论能力 × 兑现率。兑现率由 Harness 决定：

Harness 维度兑现率低（裸 Chat）兑现率高（成熟 Harness）
上下文利用手动贴，丢三落四自动注入相关文件、检索增强、压缩历史
工具利用无工具结构化工具协议（MCP / function calling），一次规划多次调用
纠错机制错了就重问自动读错误信息、改代码、重跑、验证闭环
长任务上下文爆掉子任务委派、checkpoint、断点续跑
举例：同样的 deepseek-v4-flash，在裸 Chat 里只能回答问题；在 Kevin 的 Hermes Harness 里——读研报、算 AR/CAR、调 iFinD、派子代理核验、生成 HTML、推 GitHub Pages，一次对话完成一整套投研流水线。模型没变，Harness 变了。

2.3 意义三：Harness 是「信任」的载体

企业（尤其银行）不信任「裸模型」，但可以信任「带护栏的 Harness」：权限审批、审计日志、沙箱隔离、数据不出域。WorkBuddy 白皮书的三层架构正是此逻辑——模型在最底层（L0），真正的工程工作量在 L1-L3 的 Harness 体系。

3.2 一个 Harness 的灵魂：SOUL / 人格层

在 OpenClaw / Hermes 系里，Harness 还有一个独特模块——SOUL.md / 人格定义：它决定了模型「以谁的身份、按什么原则、用什么语气」工作。

Kevin 的实证：我的 SOUL.md 定义了「研究纪律：标明 as_of、区分事实与推断、数字可追溯、给出反证条件」——同一个 deepseek-v4-flash，没有这份 SOUL 就是个聊天机器人，有它就是投研总监。人格层把「模型的能力」定向成「组织要的行为」。

5

证据：同一模型，不同 Harness

THE BENZI CASE & THE ARENA DISCREPANCY

5.1 直接证据：Benzi——「在 Sonnet 上打败 Claude Code 的 Harness」

HN 2026-08-08：「Try Benzi – A coding harness/agent beating Claude Code itself on Sonnet」

同一个 Claude Sonnet 模型，跑在 Benzi Harness 里，在基准上打败了 Claude Code（Anthropic 自家 Harness）。

→ 模型完全相同，胜负手 100% 来自 Harness 的上下文策略、工具调用方式、验证循环。

5.2 间接证据：LMArena 榜的「同模型不同榜」差异

同一模型在不同评测 Harness 下的排名剧烈变化：

模型Text 榜WebDev 榜Agent 榜说明
claude-fable-5第 1（1506）第 5（1628）第 1（+12.0%）全能王
kimi-k3-max未入前十第 2（1674）第 5（+10.4%）裸对话一般，编码 Harness 下爆发
qwen3.8-max第 9（1490）第 3（1670）—同样「编码强于对话」
deepseek-v4-flash未入前十第 8（1585）—成本 1/10，WebDev 差 <7%
解读：Text 榜测的是「裸模型对话」，WebDev/Agent 榜测的是「模型 + 评测 Harness 的协同」。Kimi K3 从「前十不入」到「WebDev 第 2」——差距全在 Harness 协同质量。这也解释了为什么「Chat 里的一般模型」到了 agent 工作流里可能吊打「Chat 里的王者」。

5.3 反面证据：Harness 翻车案例

「Accidental data loss in Claude Code and OpenAI Codex: when AI deletes user files」（HN 7/23）

同样的模型能力，Harness 的权限设计缺陷（无确认的 rm、覆盖写）导致用户数据丢失。Harness 不只是放大器，也是风险面——这也是银行要求「先审后做、沙箱隔离」的根本原因。

对 Kevin 的现实意义

WHAT THIS MEANS FOR YOUR INVESTMENT RESEARCH STACK

6.1 你的 Harness 已经是差异化资产

Kevin 的 Hermes 栈 = 22 个 OPC skills + delegation 路由 + 6 阶段 cron 流水线 + 多模态核验 + GitHub Pages 交付——这是「投研版 WorkBuddy」。这套 Harness 的价值 = 模型能力 × 投研方法论封装。

6.2 三条可执行结论

① 模型选型可以更激进地「以 Harness 为中心」：K3 / GLM / DS 三模型路由已被 LMArena 验证合理——不需要等「最强的模型」，需要「在你的 Harness 里兑现率最高的模型」。

② 你的竞争力从「会调模型」变成「会造 Harness」：面试财富管理岗时，讲「我给自己的投研工作流造了一套 Harness：采集→核验→量化→交付」比讲「我会用 ChatGPT」有说服力一个数量级。

③ 银行 ToB 的 AI 落地点 = Harness 治理：银行不缺模型，缺「可控的 Harness」——权限、审计、沙箱、数据不出域。你懂投研 + 懂 Harness 架构 = 稀缺复合人才。

6.3 一句话总结

模型是「潜能」，Harness 是「产能」。 上半场比谁的大脑强，下半场比谁的身体好。你已经在下半场的赛道上，而且跑的是自己组装的车。

结语 · 从模型到系统

FROM MODELS TO SYSTEMS

WorkBuddy 白皮书把 2026 年定义为「AI 下半场」：能力比拼从基础模型转向 Agent 应用。本文把这个判断再推进一步：

Agent 的比拼，本质是 Harness 的比拼。

ZCode、DeepSeek Harness、Claude Code、Codex、OpenClaw、Hermes——名字不同，内核相同：都在回答「如何让一个聪明但瘫痪的大脑，变成能交付结果的员工」。

对 Kevin：你已经用 Hermes 跑通了「投研 Harness」的完整范式。下一个问题是——如何把它产品化、可复制、可讲述。那才是从「超级个体」到「超级团队」的桥。
